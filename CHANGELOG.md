# Изменения

Номер версии набора лежит в `scripts/ralph/ralph-version.mjs`; его печатает
`node scripts/ralph/ralph-loop.mjs --check` и показывает шапка пульта.
Документация набора описывает текущее состояние, а что изменилось между
версиями — здесь.

Правило номера:

- Старший номер — сломанная совместимость установленного набора: удалённый или
  переименованный ключ конфига, переименованный файл, который проект копирует к
  себе. После такого обновления `.agents/ralph.config.json` правят руками; что
  именно проверять — README, раздел «Как обновить набор».
- Средний номер — новая возможность или новый необязательный ключ конфига.
- Младший номер — исправление и правка текста.

## 1.2.0 — 2026-08-31

- Добавлено поле `githubAccount` в конфиг и пульт. Ralph получает токен
  выбранного login из GitHub CLI только для своих команд `gh` и сетевых команд
  Git. Глобальный active account, Git Credential Manager и окружение агента не
  меняются. При выбранном аккаунте Ralph принимает только HTTPS origin GitHub
  без credentials.
- Добавлен `validationMode: "host"`. Ralph запускает preflight и проверки в
  рабочей папке, передаёт значения из `validationEnvironment` и отклоняет
  команды, которые меняют отслеживаемые или новые файлы. Docker в этом режиме
  не нужен. Контейнерный режим остаётся умолчанием.
- Добавлены `validationContainer.writableVolumes`. Анонимные volumes дают
  пакетным менеджерам записываемый store при read-only root filesystem и
  удаляются после проверки.
- Документация контейнера описывает настройку Corepack и pnpm store. pnpm можно
  установить при сборке образа и не скачивать перед каждой проверкой.
- Codex принимает effort `minimal`, `low`, `medium`, `high`, `xhigh`, `max`, `ultra`.
  Пульт предлагает модели GPT-5.6 Sol, Terra и Luna, GPT-5.5, GPT-5.4,
  GPT-5.4 Mini и GPT-5.3 Codex Spark, но по-прежнему разрешает своё имя модели.
- Событие Codex `turn.completed` записывает непересекающиеся категории токенов.
  Пульт не показывает строку цены, если CLI цену не прислал.
- Временный каталог сессии удаляется с повторами. Ошибка `EPERM` после
  завершения агента больше не роняет весь процесс; Ralph пишет предупреждение
  и продолжает.
- Проверка авторизации GitHub снова не называет хост, поэтому установка на
  GitHub Enterprise работает как прежде. При заданном `githubAccount`
  проверяется именно он: активный аккаунт подтверждал бы не ту авторизацию, и
  отказ приходил бы посреди прогона.
- Остановка host-проверки больше не запирает задачу: фаза `validation-mutated`
  разрешает продолжить работу с незакоммиченным diff, а сообщение называет
  изменённые файлы.
- Хеш дерева в host-режиме снимается после команд подготовки: миграции и
  генерация кода — их работа, и раньше она останавливала прогон собственным
  результатом.
- Команды host-проверки получают домашний каталог `.git/ralph-loop/host-home`.
  Без `HOME` инструменты Go, Rust, JVM и npm останавливались на поиске кэша до
  первой команды проекта; профиль оператора им по-прежнему недоступен.
- `validationEnvironment` работает и в контейнерном режиме: значения уходят в
  `docker run` переменными окружения и входят в ключ attestation.
- Адрес origin закрепляется на весь прогон. Правка `.git/config` между фазами
  останавливает прогон: иначе ветку с токеном выбранного аккаунта отправили бы
  по новому адресу.
- `validationContainer.writableVolumes` появился на вкладке «Проверки»: раньше
  поставляемый ключ показывался в блоке «Не распознано».

## 1.1.0 — 2026-08-30

Пульт перестроен: вместо вкладок сверху — боковая панель, вместо двух тем —
одна тёмная.

- Слева панель разделов «Расход», «Настройки», «Команды» с иконками; кнопка
  внизу сворачивает её до рейки из иконок, выбор переживает перезагрузку. На
  экране уже 720px панель сворачивается сама.
- У каждого раздела появился заголовок и строка под ним о том, что человек
  здесь видит и откуда эти данные: журнал прогона, файл настроек или сам набор.
  Раньше раздел называла только подпись кнопки в боковой панели, а в свёрнутой
  панели подписей не видно.
- Состояние прогона переехало из полосы под шапкой в шапку страницы, справа от
  заголовка.
- Раздел «Команды» пересобран. Строка объяснения теперь не длиннее 70 знаков —
  на всю ширину пульта она доходила до 140, вдвое больше читаемой. Три поля
  подряд читались как один абзац, поэтому каждое стало отдельной карточкой со
  своим заголовком и знаком раскрытия: «Делает» открыто у всех команд, «Когда
  звать» и «Не делает» раскрываются по клику.
- У каждой команды появился заголовок словами: «Запустить проверку», «Беклог на
  GitHub: milestones и issues». Команды терминала начинаются одним путём к
  файлу, а `/prd` и `/plan-phase` ничего не говорят тому, кто видит набор
  впервые.
- Подсказки команд переписаны: поле «Делает» говорит, что будет на выходе —
  файл, беклог, отчёт, вкладка с пультом. Раньше по ним нельзя было понять, что
  вы получите.
- Команда `node scripts/ralph/ralph-loop.mjs` без ключа убрана из справочника:
  она делает то же, что `--check`, и в списке читалась как вторая проверка.
- Команды разделены вкладками по месту набора: «В терминале» и «В чате с
  агентом». Вперемешку восемь записей читались как один длинный список.
- Сама команда набрана строкой терминала: тёмная полоса с приглашением `$` и
  кнопкой копирования у правого края. Приглашение только рисуется — ни в буфер,
  ни в выделение оно не попадает, иначе доллар уехал бы в терминал вместе с
  командой. В чате приглашения нет: там команду вводят строкой сообщения.
- Сама команда раскрашена, как в терминале: чем её запускают — приглушённо,
  путь к файлу — основным цветом, ключ — акцентом; у скилла подсвечено имя.
  Разбор идёт по пробелам, склейка частей возвращает исходную строку, поэтому
  копирование и выделение отдают команду посимвольно.
- Кнопка «Копировать» стала иконкой: подпись повторялась у каждой команды и
  спорила с ней за внимание; действие называет aria-label, успех показывает
  галочка.
- Тема одна, тёмная: пульт открывают рядом с терминалом, и светлая вкладка
  между тёмными окнами била по глазам. Палитра под системную светлую тему
  убрана.
- Страница по-прежнему не делает внешних запросов: иконки — встроенные SVG,
  новых зависимостей нет. Добавлены тесты: единственная тёмная тема, ни одной
  внешней ссылки в разметке, все три раздела достижимы.

## 1.0.3 — 2026-08-30

`templates/AGENTS.md` перестроен: наверху то, что действует в каждой задаче,
ниже — частные правила.

- Раздел «Ground rules» собрал два правила, которые раньше висели в шапке без
  заголовка: обновлять документацию и не читать `.agents/RALPH.md` в автономной
  сессии.
- Раздел «Code structure and naming» поднят выше экономии токенов: нарушение
  этих правил портит результат, а экономия только удешевляет его.
- Добавлен порог размера — около 300 строк в файле и около 30 в функции. Это
  повод проверить, нет ли у куска кода двух причин меняться, а не запрет:
  превышение само по себе дефектом не считается и не разрешает дробить код на
  однометодные обёртки.
- В разделе про инструкции появилось правило порядка: правила, которые
  действуют в каждой задаче, ставят вверху файла.

`AGENTS.md` в проекте ваш — перенесите изменения руками.

## 1.0.2 — 2026-08-30

Три теста проверяли настройки проекта, а не поведение кода. В самом наборе они
проходили: его конфиг совпадает с умолчаниями.

- Умолчание усилия рассуждений проверяется на конфиге без этого поля. Копия
  конфига без ключа его не убирала: правка накладывается на файл проекта, и
  ключ оставался из файла, поэтому в проекте с `developmentEffort: "high"` тест
  падал.
- Умолчание `syncBaseBranch` проверяется тем же способом. Раньше тест читал
  значение из конфига, и проект, выключивший слияние базы, ронял его своей
  настройкой.
- Тест prompt больше не привязан к формулировкам шаблона: текст шаблона
  принадлежит проекту. Проверяются правила, дошедшие до prompt, подстановка
  полей и запрет посылать агента в `.agents/RALPH.md`.
- README называет второй штатный пропуск теста в чужом проекте: `CHANGELOG.md`
  туда не копируют, а тест версии сверяется с ним.

## 1.0.1 — 2026-08-30

Исправления по итогам установки набора в первый посторонний проект.

- Тесты набора больше не зависят от настроек проекта. Проверка настроек
  разбирает конфигурацию в памяти вместо записи `.agents/ralph.config.json` на
  диск, а умолчание поля проверяется на конфиге без этого поля, а не на значении
  из файла проекта. Раньше пятнадцать тестов переписывали конфиг проекта, и в
  проекте с другими настройками часть тестов падала на них, а не на поведении
  кода.
- Тест, который сверяет снимок зависимостей с закоммиченными байтами,
  отмечается пропущенным, пока набор в проекте не закоммичен: сравнивать не с
  чем, и раньше он падал с сообщением git про отсутствующий в HEAD файл.
- Сборка образа валидации повторяется при обрыве связи — столько раз, сколько
  задано полем «Повторов сетевой команды» (`runtime.networkRetryAttempts`).
  Сборка — единственный шаг проверок с сетью, и обрыв на слое зависимостей
  раньше останавливал прогон целиком.
- Шаблон `scripts/ralph/Dockerfile.validation` описывает три следствия изоляции
  прогона: зависимости из образа копируются в рабочий каталог, а не отдаются
  ссылкой; база данных поднимается на старте контейнера в tmpfs и требует
  локали `C.UTF-8`; установка зависимостей переживает нестабильную сеть циклом
  повторов внутри одного шага сборки.

## 1.0.0 — 2026-08-27

Первый выпуск: сравнивать не с чем. Набор состоит из:

- цикла `ralph-loop.mjs`: берёт issues milestone по возрастанию номера, ведёт
  задачу до коммита и закрытия, держит состояние между перезапусками;
- изоляции проверок в Docker: команды валидации выполняются в контейнере из
  `scripts/ralph/Dockerfile.validation`;
- независимого ревью каждой issue отдельной сессией агента и ревью milestone
  целиком с публикацией результата в pull request;
- порога важности `reviewSeverityFloor`: замечание ниже порога не возвращает
  issue агенту, а уезжает отдельной issue с меткой `ralph-deferred`;
- журнала одобренных issues `scripts/ralph/approved-issues.json`: Ralph сверяет
  его sha256 с ключом `approvedIssueSnapshotsHash` конфига при каждом запуске,
  поэтому автономная сессия не одобрит себе задачу сама. Эталон лежит в
  `.agents/ralph.config.json`, и обновление набора его не трогает;
- журнала расхода токенов и времени по задачам и попыткам;
- пульта `ralph-gui.mjs`: расход, настройки конфига и справочник команд на
  localhost;
- правил автономной сессии `.agents/ralph-rules.md` — они уходят в prompt
  каждой issue целиком — и схемы ответа ревью `.agents/review.schema.json`;
- четырёх команд чата: `/prd`, `/plan-phase` и `/issues` готовят беклог для
  прогона, `/review-all` ревьюит готовые изменения. Текст каждой лежит в
  `.agents/skills/`, ссылка на него — в `.claude/skills/`, и тест сверяет пару
  дословно;
- трёх ревьюеров в `.claude/agents/` — `security-reviewer`,
  `correctness-reviewer` и `test-coverage-reviewer`, — которых запускает
  `/review-all`; прогон их не вызывает. Перспективы лежат в их файлах, поэтому
  CLI без субагентов проходит те же три по очереди. Важность находки они
  оценивают шкалой `P0`–`P3` из `.agents/review.schema.json`, модель берут от
  текущей сессии, а правила ревью проекта читают из необязательного
  `.agents/review-rules.md`;
- шаблонов настройки проекта в `templates/`: `AGENTS.md`, `CLAUDE.md`,
  `pre-commit`, `lint-staged.config.mjs`;
- файла `.gitattributes`: он закрепляет перевод строк LF на файлах набора, без
  которого sha256 файла одобренных issues на Windows расходится с суммой в
  конфиге и набор не стартует;
- файла `.gitignore`: он исключает результаты ревью и файлы, которые Claude Code
  пишет себе сам, — иначе они делают рабочее дерево грязным, а прогон стартует
  только на чистом;
- собственных тестов: 234 штуки, команда запуска — в README, раздел «Проверить,
  что копия цела».

Что нужно на машине: Node.js 22 или новее (набор проверен на 24), Git, GitHub
CLI, Docker и CLI агента — `claude` или `codex`. Поставляемый конфиг заполнен
под `claude`; рабочий комплект полей для `codex` описан в README.
