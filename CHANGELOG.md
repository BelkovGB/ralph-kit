# Изменения

Номер версии набора лежит в `scripts/ralph/ralph-version.mjs`; его печатает
`node scripts/ralph/ralph-loop.mjs --check` и показывает шапка пульта.
Документация набора описывает текущее состояние, а что изменилось между
версиями — здесь.

Правило номера:

- Старший номер — сломанная совместимость установленного набора: удалённый или
  переименованный ключ конфига, переименованный файл, который проект копирует к
  себе. После такого обновления `.agents/ralph.config.json` правят руками; что
  именно проверять — README, раздел «Как обновить набор».
- Средний номер — новая возможность или новый необязательный ключ конфига.
- Младший номер — исправление и правка текста.

## 2.0.1 — 2026-09-02

- Текст между маркерами `ralph-issue-review-context` в теле issue больше не
  попадает в prompt сессии. Блок Ralph дописывает сам, поэтому в одобренный
  снимок он не входит и его правка сверку снимка не роняет — любой, кто вправе
  редактировать issue на GitHub, мог продиктовать через него задание агенту и
  ревьюеру. Теперь тело issue собирается из снимка, а замечания прошлого ревью
  идут из состояния прогона в `.git/ralph-loop/`, куда их пишет сам цикл.
- Отложенная после `maxReviewFixAttempts` issue теряет замечания вместе с
  состоянием прогона: следующий прогон берёт её по одному тексту автора. Текст
  замечаний остаётся в теле issue для человека — на этом шаге в дело и вступает
  человек.
## 2.0.0 — 2026-09-02

- **Сломана совместимость.** Контейнерный режим проверок удалён целиком:
  проверки идут командами оболочки в рабочей папке проекта. Ключи
  `validationMode`, `validationContainer` и `validationDependencyPaths` больше
  не существуют — конфиг с любым из них не загружается, и отказ называет
  выпуск и способ починки. Удалите их руками или кнопкой «Удалить» в блоке
  «Не распознано» на вкладке «Настройки» пульта.
- Из поставки исчезли `scripts/ralph/Dockerfile.validation`,
  `ralph-validation-entrypoint.sh` и `ralph-validation-docker-shim.sh`.
  Обновление перезаписывает каталог набора, но не чистит его: удалите эти три
  файла из проекта сами. Docker больше не нужен ни для чего.
- Исчез механизм attestation вместе с признаком `attested` в метриках: набор
  больше не пропускает проверки по отметке о прошлом успехе. Файл
  `.git/ralph-loop/validation-attestations.json` остаётся мусором, его можно
  удалить.
- Запрет управляющих операторов `;`, `&`, `|` и обратной кавычки в командах
  проверок стал безусловным: раньше цепочка разрешалась в контейнере. Конфиг
  с цепочкой перестанет загружаться — разнесите её по отдельным строкам.
- `runtime.validationTimeoutMs` остался и означает таймаут собственного
  git-коммита Ralph; поле пульта переименовано в «Таймаут коммита».
- Отдельный прогон подготовки в начале фазы больше не считает её результат
  правкой дерева. `preflightScripts` с миграцией или генерацией кода
  останавливали прогон кодом `RALPH_VALIDATION_MUTATED` до первой issue —
  вопреки собственному контракту, по которому подготовка вправе менять дерево.
  В контейнерном режиме отпечаток дерева не снимался вовсе, поэтому отказ
  задевал только тех, кто уже выбрал проверки в рабочей папке.

## 1.7.3 — 2026-09-02

- Жизненный цикл issue закреплён in-process тестами: найденный commit доходит
  до push, ревью и закрытия; отказ ревью возвращает issue агенту, а повторный
  отказ паркует её; пройденное на прошлом прогоне ревью не повторяется. До
  этого путь после валидации проверялся только настоящим прогоном с настоящим
  GitHub. Стенд уводит git-команды цикла в одноразовый репозиторий и
  подменяет gh и CLI агента; полный прогон тестов стал дольше примерно на
  двадцать секунд.

## 1.6.0 — 2026-09-01

- `/issues` до записи в GitHub сверяет план с PRD и кодом, строит граф
  зависимостей и останавливается при цикле, ссылке вперёд, неполной цепочке,

  объяснение агента — «не могу изменить файл, он генерируется сборкой» — тоже
  не считается отказом: совпадение обрывает весь прогон.

## 1.5.1 — 2026-09-01

- Пульт снова показывает ход прогона: разбор `run.log` не учитывал отметку
  времени и уровень, которые журнал ставит каждой строке, поэтому живой шаг и

  обрывает её до строки с итогом, и её последний шаг больше не висел бы на

- Карточка хода обновляется отдельно от таблицы: раньше каждый шаг агента
  перестраивал всю вкладку и сбрасывал прокрутку и фокус на строке.
- Счётчик назван «открытых issues»: в это число входит и задача, которая идёт
  сейчас, а подпись «в очереди» завышала остаток на единицу.

## 1.0.0 — 2026-08-27

Первый выпуск: сравнивать не с чем. Набор состоит из:

- цикла `ralph-loop.mjs`: берёт issues milestone по возрастанию номера, ведёт
  задачу до коммита и закрытия, держит состояние между перезапусками;
- изоляции проверок в Docker: команды валидации выполняются в контейнере из
  `scripts/ralph/Dockerfile.validation`;
- независимого ревью каждой issue отдельной сессией агента и ревью milestone
  целиком с публикацией результата в pull request;
- порога важности `reviewSeverityFloor`: замечание ниже порога не возвращает
  issue агенту, а уезжает отдельной issue с меткой `ralph-deferred`;
- журнала одобренных issues `scripts/ralph/approved-issues.json`: Ralph сверяет
  его sha256 с ключом `approvedIssueSnapshotsHash` конфига при каждом запуске,
  поэтому автономная сессия не одобрит себе задачу сама. Эталон лежит в
  `.agents/ralph.config.json`, и обновление набора его не трогает;
- журнала расхода токенов и времени по задачам и попыткам;
- пульта `ralph-gui.mjs`: расход, настройки конфига и справочник команд на
  localhost;
- правил автономной сессии `.agents/ralph-rules.md` — они уходят в prompt
  каждой issue целиком — и схемы ответа ревью `.agents/review.schema.json`;
- четырёх команд чата: `/prd`, `/plan-phase` и `/issues` готовят беклог для
  прогона, `/review-all` ревьюит готовые изменения. Текст каждой лежит в
  `.agents/skills/`, ссылка на него — в `.claude/skills/`, и тест сверяет пару
  дословно;
- трёх ревьюеров в `.claude/agents/` — `security-reviewer`,
  `correctness-reviewer` и `test-coverage-reviewer`, — которых запускает
  `/review-all`; прогон их не вызывает. Перспективы лежат в их файлах, поэтому
  CLI без субагентов проходит те же три по очереди. Важность находки они
  оценивают шкалой `P0`–`P3` из `.agents/review.schema.json`, модель берут от
  текущей сессии, а правила ревью проекта читают из необязательного
  `.agents/review-rules.md`;
- шаблонов настройки проекта в `templates/`: `AGENTS.md`, `CLAUDE.md`,
  `pre-commit`, `lint-staged.config.mjs`;
- файла `.gitattributes`: он закрепляет перевод строк LF на файлах набора, без
  которого sha256 файла одобренных issues на Windows расходится с суммой в
  конфиге и набор не стартует;
- файла `.gitignore`: он исключает результаты ревью и файлы, которые Claude Code
  пишет себе сам, — иначе они делают рабочее дерево грязным, а прогон стартует
  только на чистом;
- собственных тестов: 234 штуки, команда запуска — в README, раздел «Проверить,
  что копия цела».

Что нужно на машине: Node.js 22 или новее (набор проверен на 24), Git, GitHub
CLI, Docker и CLI агента — `claude` или `codex`. Поставляемый конфиг заполнен
под `claude`; рабочий комплект полей для `codex` описан в README.
