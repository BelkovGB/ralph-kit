# PRD: Пульт как рабочее место оператора прогона

**Дата**: 2026-08-31

## Цель

Оператор видит на пульте, что делает Ralph прямо сейчас, чем закончилась каждая
задача, сколько это стоило и какие замечания нашло ревью, а настройку фаз и
веток заполняет выбором из того, что уже есть в репозитории, вместо ручного
переноса имён.

## Пользовательские сценарии

- Оператор открывает вкладку «Прогон» → видит цепочку задач текущей фазы: номер
  и заголовок каждой задачи, её текущий этап цикла, число попыток и итог
  последней, а над цепочкой — фазу, её ветку и то, сколько задач в ней уже
  закрыто.
- Оператор смотрит на схему цикла → видит, на каком этапе стоит задача сейчас:
  сессия агента, проверки, staging, commit, push, ревью, закрытие; пройденные
  этапы отличаются от предстоящих, а остановка помечена на том этапе, где
  случилась.
- Оператор открывает задачу в цепочке → видит замечания ревью последней попытки:
  важность, заголовок, файл и строку, — и причину остановки словами, если
  попытка не прошла.
- Оператор смотрит расход → видит счётчики по видам обращения и по ролям
  столбиками, а не только числами, и рядом ту цену, которую прислал сам CLI.
- Оператор правит настройки и нажимает «Сохранить» → пульт записывает
  `.agents/ralph.config.json` и сразу коммитит только этот файл, поэтому
  следующий `--check` не спотыкается о грязное дерево.
- Оператор нажимает «Просканировать репозиторий» на вкладке «Фазы» → пульт
  разбирает файл плана и состояние git, показывает найденные фазы, ветки и
  зависимости и предлагает заполнить ими таблицу фаз; заполнение происходит
  после подтверждения.
- Оператор выбирает файл плана из выпадающего списка `docs/plan-*.md` → пульт
  берёт из него названия фаз и их зависимости, а имена веток и milestone
  подставляет из того, что нашёл в репозитории.

## Не в скоупе

- Пульт не ходит в GitHub: ни чтения issues и milestones, ни создания их.
  Milestones и issues по плану заводит команда `/issues` в сессии агента.
- Пульт не запускает и не останавливает прогон.
- Пульт не коммитит ничего, кроме `.agents/ralph.config.json`, и не делает push.
- Переработка внешнего вида остальных вкладок: сначала функции, вид отдельной
  задачей.
- Правка плана из пульта: файл плана только читается.

## Технические ограничения

- Пульт живёт на `127.0.0.1` с разовым ключом и до сих пор менял ровно один файл.
  Коммит конфига — первое действие пульта, изменяющее историю репозитория; его
  сообщение и состав придётся закрепить, потому что hooks в этот момент
  отключены не будут.
- Без доступа к GitHub источники данных только локальные: журнал расхода
  `.git/ralph-loop/issue-metrics.json` (задачи, попытки, итоги, токены по ролям),
  состояние прогона `.git/ralph-loop/state.json` (текущая задача и её этап),
  результаты ревью `.agents/last-review.json` и
  `.agents/last-milestone-review.json` (только последнее ревью, прежние
  перезаписаны), ссылки git и trailer `Ralph-Issue: #N` в истории веток, файл
  плана `docs/plan-*.md` и конфиг. Задача, закрытая руками на GitHub, и
  замечание, уехавшее в отложенную issue, пульту не видны.
- Этапы цикла заданы кодом: `agent-running`, `working-tree`, `validating`,
  `validation-mutated`, `staging`, `committed`, `pushed`, `reviewing`,
  `review-failed`, `closing`. Схема цикла обязана называть их же, иначе она
  разойдётся с состоянием прогона.
- Взвешенного расхода в наборе больше нет: подобранные коэффициенты убраны в
  версии 1.2.2, потому что проверить их по логам или официальным ставкам нельзя.
  Пульт своих коэффициентов не заводит и ничего не взвешивает.
- Цену, которую CLI прислал сам, журнал хранит по ролям вместе со счётчиком
  `costReportedBy`. Это единственное денежное число, которое пульт вправе
  показать: набор его не вычисляет, а берёт из вывода CLI.
- Ключ `phases` проверяется при загрузке конфига: имена milestone и веток
  уникальны, ветка не совпадает со своей базой. Заполнение из скана обязано
  проходить ту же проверку до записи.
- Пока прогон идёт, форма настроек заблокирована. Коммит конфига и скан
  репозитория в это время недоступны по той же причине.
- Разбор файла плана опирается на формат скилла `plan-phase`: заголовок
  `### Фаза N: название` и строка `**Зависит от**`. Файл, написанный не по этому
  формату, пульт разобрать не обязан.
- Новых внешних зависимостей фича не требует: страница по-прежнему не делает
  внешних запросов, графики рисуются встроенными средствами.

## Допущения

- Цепочка задач строится по журналу расхода и состоянию прогона, а не по GitHub:
  доступ к GitHub оператор запретил.
- Прежние ревью недоступны, поэтому замечания показываются только для последней
  попытки; для более ранних показывается причина остановки из журнала.
- Коммит конфига делается сообщением вида `chore(ralph): обновить настройки` без
  push: отправка ветки — решение оператора.
- Скан репозитория считает фазу сделанной, если её ветка существует и её вершина
  влита в базу этой фазы; иначе фаза считается открытой.
- Зависимость фаз берётся из строки `**Зависит от**` файла плана; при отсутствии
  файла база берётся из порядка веток, а неопределённая база остаётся пустой и
  означает базовую ветку репозитория.
- Расход на пульте считается тем же кодом, что и строка итога прогона, поэтому
  числа на пульте и в терминале совпадают.
- Вкладка «Прогон» становится первой: она отвечает на вопрос «что сейчас», с
  которым пульт и открывают.

## Критерии готовности

1. При открытой вкладке «Прогон» и записях в журнале расхода система показывает
   для каждой задачи текущей фазы её номер, заголовок, этап цикла, число попыток
   и итог последней попытки словами.
2. При идущем прогоне система отмечает на схеме цикла этап, записанный в
   состоянии прогона, и обновляет отметку без перезагрузки страницы.
3. При остановке прогона на задаче система показывает на схеме цикла этап, на
   котором остановка произошла, и причину словами.
4. При наличии `.agents/last-review.json` система показывает замечания последнего
   ревью: важность, заголовок, файл и строку каждого.
5. При отсутствии или нечитаемом файле результата ревью система показывает
   строку «ревью не читается» и остальную часть вкладки рисует без него.
6. При открытой вкладке расхода система рисует счётчики по видам обращения —
   вход вне кэша, запись и чтение кэша, рассуждения, ответ — столбиками и не
   показывает ни одного числа, выведенного из цены.
7. При наличии цены, присланной CLI, система показывает её отдельным числом и
   называет, за сколько сессий из скольких она посчитана; при отсутствии — не
   показывает нулевую цену.
8. При отсутствии счётчиков токенов у сессии система показывает «CLI не прислал
   счётчики» вместо нуля в обеих величинах.
9. При нажатии «Сохранить» на вкладке настроек система записывает
   `.agents/ralph.config.json`, создаёт commit только с этим файлом и показывает
   его SHA; `git status` после этого не показывает изменений конфига.
10. При отказе коммита система показывает текст отказа и оставляет файл
   сохранённым, не откатывая правку.
11. При идущем прогоне система не сохраняет настройки, не коммитит и не
    сканирует репозиторий, а показывает причину отказа.
12. При нажатии «Просканировать репозиторий» система показывает список найденных
    фаз с их ветками, базами и признаком «сделана/открыта» и не меняет конфиг до
    подтверждения.
13. При подтверждении скана система заполняет таблицу фаз найденными значениями,
    а конфиг, который не проходит проверку `phases`, не сохраняет и называет
    причину.
14. При отсутствии файлов `docs/plan-*.md` система показывает пустой выпадающий
    список и предлагает заполнить фазы вручную.
15. При выборе файла плана система подставляет названия фаз и их зависимости из
    файла, а имена веток — из найденных в репозитории; расхождение между планом и
    репозиторием система называет строкой.
