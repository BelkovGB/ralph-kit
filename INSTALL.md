# Установка Ralph Kit в проект

Инструкция написана для агента, который ставит набор в чужой репозиторий, и для
человека, который эту установку принимает. Что такое Ralph и как он работает —
в [README.md](README.md); здесь только порядок действий и проверки.

Все пути ниже — от корня репозитория проекта. Начинайте на чистом рабочем дереве
и закоммитьте установку одним коммитом: прогон стартует только на чистом дереве,
а незакоммиченный файл набора выглядит для него незавершённой работой сессии.

## До начала

Проверьте и остановитесь, если что-то не выполняется:

- проект — git-репозиторий с remote на GitHub;
- `gh auth status` отвечает успехом, у аккаунта есть право записи в репозиторий;
- `node --version` — 22 или новее;
- `git status --short` пуст;
- Docker нужен только для `validationMode: "container"`; в режиме `host` он не
  нужен.

## Где набор обязан лежать

Каталог набора — `scripts/ralph/` в корне проекта. Вынести его в отдельный
репозиторий или в общий каталог на машине нельзя, и обходить это не нужно:

- модули считают корень проекта как два уровня вверх от собственного файла
  (`scripts/ralph/ralph-config.mjs`, `ralph-loop.mjs`, `ralph-git.mjs` и ещё
  пять); из другого места они укажут не на тот корень;
- все команды Git и GitHub выполняются в этом корне;
- снимок для контейнера проверок собирается из `git ls-files` проекта, поэтому
  файлы набора обязаны лежать в его индексе — иначе проверки останутся без
  скриптов Ralph;
- версия набора видна в истории проекта: `--check` печатает её, а `git log`
  показывает, каким коммитом её подняли.

Обновление устроено не выносом, а перезаписью каталогов набора. Порядок — в
разделе «Обновление».

## Что скопировать

| Путь в проекте | Владелец | При обновлении |
| --- | --- | --- |
| `scripts/ralph/**` | набор | перезаписать целиком |
| `.agents/RALPH.md`, `.agents/ralph-rules.md`, `.agents/review.schema.json` | набор | перезаписать |
| `.agents/skills/**` | набор | перезаписать |
| `.claude/skills/**`, `.claude/agents/**` | набор | перезаписать |
| `LICENSE` рядом с копией, например `scripts/ralph/LICENSE` | набор | перезаписать |
| `.agents/ralph.config.json` | проект | не трогать |
| журнал одобренных issues | проект | не трогать |
| `AGENTS.md`, `CLAUDE.md` в корне | проект | не трогать |
| строки в `.gitattributes` и `.gitignore` | проект | сверить со списком ниже |

`.agents/ralph.config.json` при первой установке берут из набора как образец и
дальше правят; при обновлении его не перезаписывают.

В проект не копируют: `README.md`, `CHANGELOG.md`, `INSTALL.md`, каталоги
`docs/`, `templates/` и `.github/`. Они описывают сам набор и остаются в его
репозитории; `templates/` разбирается ниже отдельно.

## Скиллы и субагенты остаются в проекте

Вынести их некуда: CLI ищет их по фиксированным путям внутри репозитория. Codex
читает команды из `.agents/skills`, Claude Code — из `.claude/skills`,
субагентов ревью — из `.claude/agents`.

Тело каждой команды лежит в одном месте — `.agents/skills/<имя>/SKILL.md`, а
`.claude/skills/<имя>/SKILL.md` содержит ссылку на него. Копируйте оба каталога
вместе: без первого команда в Claude Code откроет пустую ссылку.

Субагенты `.claude/agents/**` нужны обоим CLI. Есть у CLI субагенты — команда
`/review-all` раздаёт им перспективы ревью параллельно; нет — читает те же файлы
по очереди.

## Что дописать в файлы проекта

Эти файлы у проекта обычно уже есть. Не заменяйте их, а дописывайте строки.

`.gitattributes` — одна строка:

```text
scripts/ralph/** text eol=lf
```

Без неё Git на Windows подставит CRLF при клоне, сумма журнала одобренных issues
разойдётся с эталоном в конфиге, и не запустятся ни `--check`, ни `--run`.

`.gitignore` — четыре строки:

```text
.agents/last-review.json
.agents/last-milestone-review.json
.claude/settings.local.json
.claude/scheduled_tasks.lock
```

Первые две — результат ревью, который пишет сам Ralph; вторые две инструмент
пишет себе под конкретную машину. Прогон стартует только на чистом дереве, а
`git status` считает грязным и неотслеживаемый файл.

`AGENTS.md` и `CLAUDE.md` в корне проекта: если их нет — скопируйте
`templates/AGENTS.md` и `templates/CLAUDE.md`. Если есть — не заменяйте, а
допишите недостающие разделы из шаблонов. Агент читает `AGENTS.md` в каждой
сессии, поэтому в нём должны быть стек, расположение частей кода и точные
команды сборки, линта и тестов.

## Что настроить

Значения конфига правьте на пульте: он подписывает каждое поле и проверяет ввод
теми же правилами, что и запуск прогона.

```bash
node scripts/ralph/ralph-gui.mjs
```

Порядок:

1. **Журнал одобренных issues.** Поставьте `approvedIssueSnapshotsFile` в
   `.agents/approved-issues.json` и создайте файл с содержимым `{}`. Значение по
   умолчанию — `scripts/ralph/approved-issues.json`, то есть внутри каталога,
   который обновление перезаписывает целиком; журнал проекта туда класть не
   стоит. Затем запустите `--check`: он назовёт сумму SHA-256 журнала, её
   впишите в `approvedIssueSnapshotsHash`.
2. **Режим проверок.** `host` — команды идут в рабочей папке проекта и
   используют уже установленные зависимости и запущенные рядом службы.
   `container` — изоляция и воспроизводимая среда, нужен Docker и настроенный
   `scripts/ralph/Dockerfile.validation`.
3. **Команды проверок.** `preflightScripts` — подготовка (миграции, генерация),
   `validationScripts` — сами проверки. По одной готовой команде на строку.
4. **Артефакты проверок.** `validationArtifactPaths` — каталоги, которые
   проверки создают сами: отчёты, трассы, покрытие. Ralph удалит их перед
   прогоном, иначе отчёт прошлой итерации попадёт под следующий линтер.
5. **Фазы.** Одна фаза — один milestone GitHub и своя ветка. Название milestone
   копируется из GitHub посимвольно.
6. **Агент и модели.** `agentCli` — `claude` или `codex`; модели и effort для
   разработки, ревью issue и ревью milestone.

На первый прогон включите `stopAfterFirstIssue`: Ralph сделает одну задачу и
остановится, не создавая pull request.

## Проверка установки

```bash
node scripts/ralph/ralph-loop.mjs --check
```

Команда печатает версию набора, фазу, milestone, ветку, состояние рабочего
дерева, бюджет итераций и следующую issue. Установка принята, когда `--check`
проходит без ошибок на чистом дереве.

Тесты самого набора можно прогнать в проекте — ключ обязателен, тесты делят
рабочее дерево:

```bash
node --test --test-concurrency=1 "scripts/ralph/*.test.mjs"
```

Скопированные файлы и заполненный конфиг закоммитьте: прогон стартует только на
чистом дереве.

## Обновление

1. Сверьте версии: `--check` печатает версию установленного набора, `CHANGELOG.md`
   набора — что менялось. Прочитайте все записи между вашей версией и новой.
   Старший номер означает сломанную совместимость и ручную правку конфига.
2. Перезапишите каталоги набора целиком: `scripts/ralph/**`, `.agents/skills/**`,
   `.claude/skills/**`, `.claude/agents/**` и три файла `.agents/RALPH.md`,
   `.agents/ralph-rules.md`, `.agents/review.schema.json`.
3. Не трогайте `.agents/ralph.config.json`, журнал одобренных issues, `AGENTS.md`
   и `CLAUDE.md`: это файлы проекта.
4. Сверьте строки `.gitattributes` и `.gitignore` со списком выше: набор мог
   добавить новые.
5. Запустите `--check` и закоммитьте обновление отдельным коммитом, не смешивая
   его с работой над проектом.

Обновление во время прогона не начинайте: правка файлов набора при живом прогоне
останавливает работу — проверка неизменности control plane считает это подменой.

## Удаление

Удалите `scripts/ralph/`, `.agents/RALPH.md`, `.agents/ralph-rules.md`,
`.agents/review.schema.json`, `.agents/ralph.config.json`, `.agents/skills/`,
`.claude/skills/`, `.claude/agents/`, журнал одобренных issues и каталог
`.git/ralph-loop/` с состоянием прогонов. Снимите добавленные строки из
`.gitattributes` и `.gitignore`. `AGENTS.md` и `CLAUDE.md` останутся вашими.
