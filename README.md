# Ralph Kit

## Что это

Ralph — оркестратор автономной разработки: берёт открытую issue из вехи
(milestone — папка задач в GitHub), отдаёт её агентскому CLI, прогоняет проверки
в контейнере без сети, делает один коммит, отправляет ветку и получает ревью от
отдельной модели. Вокруг него лежат правила автономной сессии, три
субагента-ревьюера, скиллы для ручного планирования (PRD → фазы → issues) и
шаблоны файлов инструкций. Кит собран из рабочего проекта и намеренно урезан:
код, заточенный под тот стек, удалён, а не спрятан под настройку.

## Что нужно на машине

- Git — цикл работает ветками и коммитами.
- `gh` (GitHub CLI) с выполненным `gh auth status` — через него идут issues, вехи и PR.
- Docker — проверки выполняются в контейнере, демон должен отвечать на `docker version`.
- Node.js — на нём написаны скрипты цикла.
- CLI агента: `claude` или `codex`. Для `claude` нужна переменная окружения
  `CLAUDE_CODE_OAUTH_TOKEN` (работает по подписке) либо `ANTHROPIC_API_KEY`
  (тарифицируется отдельно).

## Что копировать в проект

В корень репозитория, сохраняя пути:

- `scripts/ralph/` — сам цикл, Dockerfile проверок, тесты.
- `.agents/` — конфиг `ralph.config.json`, правила автономной сессии
  `ralph-rules.md`, схема ревью `review.schema.json`, операторская документация
  `RALPH.md`.
- `.claude/` — субагенты-ревьюеры (`agents/`), скиллы планирования (`skills/`),
  пример `launch.json`.
- `templates/AGENTS.md` и `templates/CLAUDE.md` → в корень как `AGENTS.md` и
  `CLAUDE.md`.
- `templates/pre-commit` → `.git/hooks/pre-commit` и
  `templates/lint-staged.config.mjs` → в корень, если нужен хук перед ручным
  коммитом.

Каталог `templates/` и этот файл в проект не переносите.

## Что переписать под свой проект

1. `scripts/ralph/Dockerfile.validation` — базовый образ и установка
   зависимостей. Во время прогона сети нет, поэтому базу данных и браузер образ
   получает при сборке.
2. `.agents/ralph.config.json`, ключи `preflightScripts` и `validationScripts` —
   готовые команды оболочки (`npm run lint`, `pytest -q`), а не имена скриптов
   пакетного менеджера.
3. `.agents/ralph.config.json`, остальное: `phases` (точное название вехи и
   ветка на каждую фазу), `baseBranch`, `trustedIssueAuthors`, модели и
   `"active": true` — в примере прогон выключен.
4. `AGENTS.md` в корне — стек, расположение кода, точные команды сборки, линта и
   тестов. Агент читает его как контракт задачи.
5. Правила безопасности для ревьюера. `.claude/agents/security-reviewer.md`
   знает только универсальные классы уязвимостей; правила проекта положите в
   `.agents/security-rules.md` или в скилл
   `.claude/skills/security-review/SKILL.md` — в ките этих файлов нет, ревьюер
   работает и без них.
6. `templates/pre-commit` и `templates/lint-staged.config.mjs` — свои команды
   вместо примеров.

Запуск: `node scripts/ralph/ralph-loop.mjs --check` проверяет настройку и ничего
не меняет, `node scripts/ralph/ralph-loop.mjs --run` выполняет прогон.

## Пульт

`node scripts/ralph/ralph-gui.mjs` поднимает страницу на этой же машине и
открывает её в браузере. Две вкладки: расход по задачам и настройки.

Расход считается по журналу `.git/ralph-loop/issue-metrics.json`: сумма, число
задач и попыток, стоимость и время каждой задачи, разбивка попытки на код,
проверки и ревью. Журнал хранит последние 200 попыток, а ревью всей вехи в него
не попадает — страница говорит об этом прямо.

Настройки правят `.agents/ralph.config.json` через форму с подсказками к каждому
полю. Значения проверяются теми же правилами, что и при запуске прогона, поэтому
ошибку показывает текст самого Ralph.

Пока идёт прогон, форма заблокирована: правка файла настроек во время работы
обрывает текущую задачу, потому что цикл считает её подделкой доверенного файла.
Изменения вступают в силу со следующего прогона.

Пульт слушает только `127.0.0.1` и требует разовый ключ из адресной строки, так
что открыть его с другого устройства нельзя.

Одна шероховатость: пульт записывает файл настроек стандартным отступом JSON. В
проекте, где `.agents/ralph.config.json` попадает под `prettier`, после
сохранения прогоните форматирование, иначе проверка формата покраснеет.

## Что решить до первого прогона

- **Откуда задачи.** Ralph берёт только открытые issue перечисленных вех,
  написанные заранее человеком. При `autoApproveConfiguredIssues: true` он
  замораживает текст issue доверенных авторов, и правка в GitHub после старта
  останавливает прогон. Если задачи закрепляются вручную в
  `scripts/ralph/approved-issues.json`, вместе с файлом придётся обновить
  контрольную сумму `approvedIssueSnapshotsHash` в
  `scripts/ralph/ralph-config.mjs`.
- **Что произойдёт при мерже.** Ralph открывает draft PR и не мержит его, но
  ветку отправляет. Проверьте, не запускает ли push или открытый PR деплой.
- **Второе автоматическое ревью.** Если на PR уже висит бот-ревьюер, ревью
  станет два: замечания бота Ralph не читает, а его собственные замечания бот
  дублирует.
- **Правила репозитория.** Ralph коммитит и пушит от вашего имени. Защита
  ветки, обязательная подпись коммитов, CODEOWNERS или запрет прямого push
  остановят цикл.
- **Вес файлов инструкций.** `AGENTS.md` и `.agents/ralph-rules.md` целиком
  попадают в prompt каждой issue: лишняя страница оплачивается на каждой задаче.
- **Насколько строгое ревью.** `reviewSeverityFloor` решает, какое замечание
  останавливает работу. В примере стоит `"P1"`: блокируют только P0 и P1, а
  остальное уезжает отдельными issue с меткой `ralph-deferred`. Значение `"P3"`
  блокирует всё и делает прогон заметно дороже: на исходном проекте 25 задач
  заняли 83 попытки, и 40 из них отклонило ревью.
- **Один прогон за раз.** Пока идёт `--run`, не запускайте второго Ralph и не
  работайте в этом репозитории второй сессией Claude Code: она пишет в
  `.claude/**`, а этот каталог входит в защищённый набор файлов (control plane),
  и правка выглядит как подделка.

## Чего в ките сознательно нет

- Выборочного запуска проверок по изменённым файлам — выполняется весь набор.
- Дешёвой дорожки для правок только в комментариях — они проходят полную
  валидацию.
- Предвычисленных направлений аудита для ревьюера — он проверяет каждый
  изменённый файл и каждый критерий готовности.

Всё это было написано под конкретный стек: настроить заново под свой проект
дешевле, чем разбирать и чинить чужие правила.

## Цена

Ralph написан на Node.js, поэтому Node нужен на машине даже проекту на Python
или Go.
